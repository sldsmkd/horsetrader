Unity — local Google OAuth spike

Proves the provider is set up and shows what comes back. This is a de-risking spike, not the production flow: Unity's real auth is a confidential-client auth-code exchange done in the Worker (the client secret never touches this file). Here we just confirm the round-trip and inspect the identity claims — chiefly sub, the (provider, providerUserId) Unity keys a save on.

Set your Client ID first. Edit CLIENT_ID at the top of this file with the OAuth Web application client ID from Google Cloud Console, then reload. Register http://localhost:8000 as an authorised JavaScript origin (and http://localhost:8000/ as a redirect URI).

1. Sign in (id_token — the identity)

The standard button + popup. Returns a signed JWT (id_token).

2. Get an access token (bearer — optional)

A separate popup that yields an OAuth2 access/bearer token (for calling Google APIs). Unity doesn't need this — identity is enough — but you asked to see a bearer token.
