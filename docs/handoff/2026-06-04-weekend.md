## 1. The five rules (these override your instincts)

1. **Docs are the source of truth.** Start at [`../README.md`](../README.md). If
   code, a stale comment, a branch name, or your own memory contradicts the docs,
   **the docs win** — and if you find a doc that's wrong, *fix the doc*, don't
   paper over it.

2. **One side per session.** This is a monorepo with two halves:
   - **ETL** (Python pipeline) — repo root + [`../etl/`](../etl/).
   - **Site** (TypeScript planner) — [`horsetrader.site/`](../../horsetrader.site/)
     + [`../frontend/`](../frontend/).

   They share a *contract* ([`../contract.md`](../contract.md)) but not a session.
   **If a task pulls you across the line (backend ↔ frontend), stop and leave a
   note rather than crossing.** This is workflow discipline, not a git rule — it
   keeps changes reviewable. Each task below is tagged `[ETL]` or `[SITE]`.

3. **JP is the substrate; EN is projected.** On the ETL side, always build from the
   JP scrape. Never build from the EN YAML — that inverts the model and is the #1
   way agents get lost here. (See [`feedback_jp_is_substrate`] in the project memory
   / [`../etl/data-sources.md`](../etl/data-sources.md).)

4. **Trust the bake.** Frontend bundle lookups *resolve or throw* — never guard a
   lookup with `undefined`. The ETL guarantees referential integrity, so a miss is
   a bug to surface, not a case to handle. (The exception is the scraped-input
   warn-and-skip path on the ETL side — that one *is* lenient by design.)

5. **Curated YAML fails loud.** Hand-curated `config/*.yaml` should `raise` on bad
   data — the pipeline run is the editor's feedback loop. *Scraped* extractors stay
   warn-and-skip. Don't swap one discipline for the other.

When in doubt, prefer **leaving a clear note over guessing**. A half-done task with
a good handoff note is worth more than a confident wrong turn.

## 2. Getting set up & verifying your work

### ETL (Python)
Full setup in [`../etl/onboarding.md`](../etl/onboarding.md). Short version:

```bash
python3.14 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python main.py            # runs the whole pipeline, one-shot
```

- **Use the warm cache — don't blow it away.** It lives at the repo-root
  `.cache/`. A cold run politely rate-limits and takes a long time *on purpose*.
  For an offline run against the existing cache, set
  `HORSETRADER_SKIP_CACHE_REFRESH=1`.
- The N+1 first-fetch loop in extractors is **not a bug** (see onboarding.md).

### Site (TypeScript)
```bash
cd horsetrader.site
npm install
npm test                  # headless unit tests — your fastest feedback loop
```
- To see it in a browser, there should already be a **dev server on `:3000`**
  (`make dev` / `make serve` from the repo root). **Probe `:3000` and reuse it** —
  don't stop/start your own. If it's down, ask once, then start it.
- Verify visual changes by driving the running server, not by guessing from code.

### Where things land
- ETL output bakes to `$HORSETRADER_TARGET/site/` (JSON + images). The shippable
  artifact is the gitignored root `static/`.
- Don't re-enable `make deploy` (wrangler) — it's deliberately stubbed for the
  live prototype.
