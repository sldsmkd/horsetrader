# Eclipse 4 — The Registry

_The concrete roster: every stream under the settled model, derived from
AUDIT.md's 13 producers + a census of the real bake (2026-06-12, 802 records).
The model is 2.DESIGN.md; the boundary is 3.INTERFACE.md; this is what goes in
the `streams` construction input. Two derivations below amend the design where
the data contradicted an assumption — flagged inline._

## The count

AUDIT's 13 producers → **10 streams + 2 shared rules + 1 reconciliation rule**:

- 10 registry entries (below).
- `generator` + `sequence` dissolve into a shared **facet-expansion rule** used
  by owning streams (derivation 2) — beside `GradedStamp`, not beside streams.
- `spends` was already dissolved into the coordinator's reconciliation pass
  (2.DESIGN) — never a registry entry.

## ⚠ Derivation 1 — claims are TYPES, not key prefixes (amends 2.DESIGN)

2.DESIGN settled `claims` = stable-key prefixes, resting on "every prefix routes
to exactly one stream" (the post-#62 invariant). The census falsifies it:

```
type                    key prefix    routing
mission            161  mission-     play-gated   (play.missions)
anniversarymission  29  mission-     universal    (ground truth)
scenariomission      4  mission-     universal    (ground truth)
banner: trainee    192  banner-      universal    (ground truth)
banner: support    156  banner-      universal    (ground truth)
```

Prefix is consistently **coarser-or-equal to type**, in both directions of
harmlessness: `banner-` spans two types that route the same (fine); `mission-`
spans three that route differently (fatal). Routing demonstrably needs type
granularity.

An ETL ask could restore prefix claims — re-key so the first token is
byte-for-byte the `type` (precedent: #62 deleted the anchor keys on Eclipse's
request; raise the ask when it's the best approach). But priced out, it buys
nothing: prefix=type alignment makes the first token a *redundant copy of the
type field*, so claims-by-prefix becomes claims-by-type with extra steps — plus
a re-key migration across everything keyed by stable keys (curated YAML,
commitments, bookmarks, dotMarks; breakage is allowed in prototype, but spend
it on something that purchases capability).

So on merits, not by constraint: **`claims` = a set of event `type`s** — the
bake's own taxonomy, disjoint by construction (one per record,
msgspec-guaranteed), so the partition assertion is trivial and the double-pay
impossibility survives unchanged. `ground.events` claims the complement of all
claimed types. This is also what the live code actually routes on
(`isMissionEvent` tests `type === "mission"`, not a prefix), and the PvP trio
are already distinct types — future claimers come free.

What survives of the prefix story: **emission `source` = the event's stable
key** is untouched (attribution joins on exact key, never on prefix), and
synthesisers still mint under reserved key *prefixes* — the prefix discipline
moves from routing baked events to fencing minted ones (below).

## Derivation 2 — facet ownership is total; generator/sequence dissolve

Census: 91 records carry a compound facet, and they mix facets on one key —
`legendrace` (47 of 54: discrete **and** sequence), `anniversarymission` (25 of
29: discrete **and** sequence), `holiday` (12 of 16: generator or sequence).

Today three streams read the *same* records split by reward facet: `events`
skips the nested shapes ("generator — separate channel"), `generator`/
`sequence` extract exactly those. That is co-ownership with mutual-exclusion
knowledge spread across stream comments — under disjoint claims it is a double
claim, and "no stream knows another exists" forbids the carve-out.

So: **an event's owner settles ALL its facets.** One shared rule (the
facet-expansion twin of `GradedStamp`):

- The owner emits the event itself (visible, discrete face) **plus minted
  cadence children** for each compound facet — one `visible: false` event per
  payout day, keyed under the parent (`<parent-key>-day-<n>`), each carrying
  that day's payload as its face. Children inherit the parent's prefix, hence
  the parent's owner — no partition issue, and ledger attribution stays
  exact-key joinable.
- The fold stays generic: a child is a one-day event paying at its own `end`.
  Per-day cadence needs no special fold path — it's just more events. Rushing
  moves only the parent's discrete face (children are dated facts; unchanged —
  matches the shipped rule).
- `generator`/`sequence` become *shapes the rule expands*, not streams. Their
  channel toggles disappear; toggling the owner toggles the whole settlement.

All current compound carriers sit in `ground.events`' complement except
`anniversarymission` (universal → also `ground.events`), so in practice the
rule has one client today — but it is declared shared because any claimer whose
type grows a compound facet must settle it identically.

Mint-prefix fence: the five minted prefixes (`routine-`, `team-`, `shop-`,
`club-`, `daily-`) collide with **no baked first token** (census: `anniversary,
mission, cm, factorstudies, holiday, leagueofheroes, legendrace,
masterschallenge, racingcarnival, scenario, showtime, skilltest, story,
strongestteam, banner, training`). Asserted at construction alongside claim
disjointness — a synthesiser declares its mints exactly as a claimer declares
its claims, and the constructor checks mints ∩ baked prefixes = ∅ and mints
pairwise disjoint. Expansion children are exempt (they mint under the parent's
own key, inside its claim).

## Enabled is PRESENCE, not pricing

The one semantic every entry had to decide: a disabled claimer's events leave
the settled world — **off the ledger and off the lane** (render source = fold
input, by construction). So each stream chooses which lever it means:

- **Gate** (`enabled`) when opting out should remove the cards too:
  `play.missions` — a "no" player's 161 grindy mission cards vanish. This is
  today's `hiddenKinds` UI hack, now falling out of the model for free.
- **Face** (the row) when the cards must stay regardless of play: CM at `skip`,
  a proto-era story, an unsubscribed training pass — always-enabled, the event
  renders with an unpriced/free-track face. "Be sweetie" answers as *which
  events, priced how* — never as presence-of-the-world's-fixtures.

Claims are **static** either way: a disabled stream's claims still partition
(its types do NOT fall back to `ground.events`' complement — gating drops the
events, it never re-routes them).

Synthesisers gate freely (their events are `visible: false` cadence — presence
and pricing coincide). The dev toggle (`setEnabled`) is the same mechanism
applied ephemerally, sound by the linear fold.

## Constructor obligations (the registry's own assertions)

1. **Claim disjointness** — no type claimed twice; exactly one complement
   claimer (`ground.events`).
2. **Mint fencing** — minted prefixes pairwise disjoint and disjoint from every
   baked first token.
3. That's all. No ordering (streams commute), no capability classes (one
   `Stream` shape), no introspection. An ill-formed registry fails to
   construct, not to fold.

## Open

- **Child key convention** — `<parent-key>-day-<n>` vs `<parent-key>-<date>`.
  Date-keyed reads better off the ledger (`legendrace-X-2026-06-14 +50`);
  day-indexed is cheaper to mint. Cosmetic; settle in TS.
- **`scenariomission` / `anniversarymission`** — universal, so they ride the
  complement into `ground.events` with no entry of their own. If either ever
  grows a gate or a graded face, it becomes a one-line claimer; nothing to
  pre-build.
- **PvP trio (#61)** — future `GradedStamp` occupants 3–5 (CM's siblings);
  each will be a one-row claimer on its own type (`leagueofheroes`,
  `strongestteam`, `masterschallenge` are already distinct types — the claims
  unit handles them for free).
