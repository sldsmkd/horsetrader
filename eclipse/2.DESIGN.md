# Eclipse 2 — The Design

_The settled model, stated cold. Derivation and superseded alternatives live in 1.NORMALISATION.md; this is what gets built._

**The loop:** shields write account state; streams read it into events; the fold reads events into money; surfaces read both; repeat. Nothing else moves.

## Currency
- **Streams produce EVENTS, not rewards.** Rewards are a property of events; money is a fold over them; cards are a view over them. One currency, two projections — the ledger and the lane.

## Stream
- `Stream = id + enabled(ctx) + claims + events(ctx) → list[Event]`. One verb.
- `id` — dotted `flow.selector.name` (`income.play.routine`, `spend.commitment.banners`). Names the stream; never names events.
- `enabled(ctx)` — the on/off gate, owned by the stream. Whole-stream gating is safe by commutativity.
- How a stream makes its events is private: **claimers** price the baked events they own (stamp a play-graded row, pass through, filter); **synthesisers** mint events the bake doesn't carry (`routine-dailies-<date>`, `visible: false` — on the ledger, off the lane).
- Streams are mutually anonymous. No stream knows another exists; no ordering between them.
- Shared rule `GradedStamp` (N=2: champions-meeting, stories; PvP trio #61 next): return own claimed events priced by the play-selected `reward_maps` row; `row(ctx, event)` is the sole varying part.

## Partition
- `claims` = stable-key prefixes (`("cm-",)`, `("story-",)`). Stable keys are routable by design (split on first `-`).
- Disjointness asserted at registry construction — double-pay is unconstructible. `income.ground.events` claims the complement.
- Uniqueness within a claim is the bake's guarantee (msgspec map): trust the bake; a collision is a bug.
- Emission `source` = the event's stable key. Minted keys give sub-source attribution for free; one naming system.

## Coordinator
- assert partition → **union = the settled world** → one generic fold → `P_income` → late pass → `P_final`.
- The settled world is simultaneously the render source (cards = its visible events, reward faces included) and the fold input. "What am I rendering?" is answered by construction.
- Money derivation exists ONCE, in the fold: pay at `end`, `start` when rushed, `flatPayload` the rewards. Payment timing is unwritable in streams.
- **The fold is linear**: `balance = base + Σ deltas`. No clamping, no min/max, no balance-conditionals — negative free carats are allowed and meaningful. Linearity + disjoint claims ⇒ streams commute; registry order means nothing; per-stream dirty/refold is legal (unbuilt — full regenerate ships).
- The coordinator holds the settled world and both boundary projections. It has no ordering responsibility and never introspects a stream.

## The late wall
- A spend is not an event — it's a claim against the fold's result. The currency genuinely changes here; this wall survives every refactor.
- `LateStream`: `emit(ctx, income) → emissions`. Runs after `P_income` exists. Spends, N=1.
- Sorting rule for new producers: **needs the balance to know what it emits → late pass; otherwise → stream.** (Sink-vs-source is the wrong axis; balance-reader is the load-bearing one.)
- Ordering is real only inside a late pass (spends sorts its own banners earlier-by-start), never between streams.
- `available` = coordinator query against `P_income` (not `P_final`), re-running the pure ordered pass, self-excluding by construction.

## Read / write
- **The projection is never written — only derived.** Account state (snapshot, commitments, play, identity, subscriptions) is the write store; the fold is a pure query over `(bake, account state)`; ctx is frozen for a fold's duration.
- One write path: shields are transactional editors over account-state fields (commit pity ≡ change a play slider — same operation, different field). COMMIT → mark dirty → re-derive → refresh views.
- A commitment is a stored claim, read fresh by every fold; a fully-spent past dissolves into the snapshot base. Nothing needs reversing because nothing was written: re-derivability, not reversibility.
- Bake immutable; the settled world lives one fold; never derive from a derived world.
